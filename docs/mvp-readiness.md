## Live acceptance sequence

1. Configure root `.env` locally using `.env.example`; set the actual Slack workspace, allowlisted channel and owner IDs, plus ClickHouse and OpenAI settings. Use `DRII_ANALYSIS_MODE=live`.
2. Run `npm run doctor`, then schema setup, corpus seed or document import, and `npm run doctor -- --live`. The live doctor makes small synthetic model/embedding calls, but sends no Slack messages and writes no records.
3. Opt into `DRII_LIVE_TESTS=1 npm run test:integration` using the shell-appropriate environment syntax. Run `npm run eval:model` separately and inspect its source-supported findings.
4. Complete the [Slack loop](workflow.md#complete-slack-loop) with another teammate, including evidence inspection, recipient reply, revised conditions, owner approval, restart and source read-back. Rehearse a provider failure and record actual latency.

The root `.env` was absent during this implementation. These account-dependent gates remain open. The repository's open issue list must not be treated as completed solely because offline tests pass.

## Deployment and sponsor boundaries

The implementation uses the existing OpenAI SDK, ClickHouse client and Slack Bolt/Block Kit stack. The [sponsor reference](https://github.com/CopilotKit/agents-everywhere-starter-kit/blob/main/using-sponsor-tools.md) is setup guidance for choosing relevant integrations; unused sponsors are not claimed as installed capabilities. Credentials stay server-side.

Self-hosted ClickHouse can be configured as an endpoint, but this remains a cloud-connected Slack/inference workflow. Fully on-prem operation requires separate replacements for communication, transcription, reasoning, embeddings and operational data handling. Dedicated robot hardware and a regulated deployment are beyond the agreed MVP.
